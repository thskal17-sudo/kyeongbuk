그런 날은 메일에 표시되고, 끝에서 한 번 더 시도하며, 접속이 안 된 곳은 같은 실행 안에서 새 서버를 받아 다시 수집합니다 (`catch-up` 작업).

### 공고를 더 정확하게 거르는 장치 (부산판과 같음)

- **결과공고가 올라오면 모집 끝으로 처리**: 같은 게시판에 나중에 '서류심사 결과·최종합격자·채용 완료' 같은 글이 올라오면
  그 모집 공고는 신규·진행중에서 뺍니다.
- **첨부 공고문에서 마감일 찾기**: 본문에 '붙임 공고문 참조'만 있는 공고는 첨부 HWP·HWPX·PDF 를 열어 접수기간을 찾습니다.
- **여러 게시판에 올라온 같은 공고는 한 번만**: 경북교육청 본청 ↔ 교육지원청처럼 같은 공고가
  두 곳에 올라오면 먼저 저장된 것만 보냅니다 (제목이 같고 게시일이 7일 안, 시·군이 맞을 때).
- **자원봉사자·늘봄실무사·조리실무사**처럼 '강사·방과후·늘봄' 낱말이 들어가도 강사 채용이 아닌 글은 뺍니다.

## 설정 방법 (처음 한 번)

### 1. Gmail 앱 비밀번호 만들기

부산·울산판과 같은 계정을 쓰면 이미 만든 앱 비밀번호를 그대로 쓰면 됩니다.

1. 보내는 데 쓸 Google 계정에 [2단계 인증](https://myaccount.google.com/signinoptions/two-step-verification)을 켭니다.
2. [앱 비밀번호](https://myaccount.google.com/apppasswords)에서 새 앱 비밀번호(16자리)를 만듭니다.

### 2. GitHub Secrets 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret** 에서 등록합니다.
부산 저장소(busan-school-company)와 같은 값을 쓰면 됩니다.

| 이름 | 값 | 필수 |
|---|---|---|
| `SMTP_USER` | 보내는 Gmail 주소 | ✅ |
| `SMTP_APP_PASSWORD` | 위에서 만든 앱 비밀번호 16자리 | ✅ |
| `MAIL_TO` | 받는 주소 (여러 명이면 쉼표로 구분). 비우면 `SMTP_USER` 로 보냄 | |
| `WORK24_API_KEY` | [고용24 Open API](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do) 채용정보 인증키 | |

- `WORK24_API_KEY` 가 없으면 고용24만 건너뛰고 나머지는 정상 수집합니다 (수집현황에 '설정필요'로 표시).
- `SMTP_USER`·`SMTP_APP_PASSWORD` 가 없으면 메일을 켠 실행은 실패합니다 (메일을 끈 시험 실행은 됩니다).

### 3. 매일 실행 브랜치

GitHub 예약 실행(cron)은 저장소의 **기본 브랜치**에 있는 워크플로만 돌립니다.
이 코드가 기본 브랜치에 있어야 매일 06:17 에 자동으로 실행됩니다 (Secrets 를 넣기 전에 예약 실행이 돌면 메일 단계에서 실패하고, GitHub 가 실패 알림을 보냅니다).

### 4. 시험 실행

**Actions → 매일 강사 공고 수집·메일 발송 → Run workflow** 를 누르면 바로 한 번 실행됩니다.

- **메일 발송** 칸을 끄고 실행하면 수집·엑셀만 하고, 결과는 실행 기록의 로그와 Artifacts(엑셀)에서 봅니다.
- 메일을 켜고 실행해서 메일이 오면 설정 완료이고, 이후 매일 자동으로 실행됩니다.
- 첫 메일에는 최근 45일 안에 올라온, 마감 전 공고가 모두 신규로 들어갑니다.
- 실행이 실패하면 GitHub 가 저장소 주인에게 실패 알림 메일을 보냅니다.

### 5. 한국 PC 실행기 설치 (해외 차단 사이트용)

해외 접속을 막는 시·군 누리집 14곳을 읽으려면 **매일 아침 05:47 무렵 켜져 있는 한국 PC** 가 하나 필요합니다
(사무실 PC 등. Windows 10/11 기준, Mac·Linux 도 됨). 설치하지 않아도 나머지 132곳은 그대로 수집되고, 메일에 '한국 PC 미실행' 으로만 표시됩니다.

1. **프로그램 두 개 설치** (이미 있으면 건너뜀)
   - [Python 3.12](https://www.python.org/downloads/windows/): 설치 첫 화면에서 **Add python.exe to PATH** 체크 →
     **Customize installation → Install Python for all users** 체크 (실행기를 서비스로 돌릴 때 필요)
   - [Git for Windows](https://git-scm.com/download/win): 기본 설정 그대로 설치
2. **실행기 등록**: 저장소 **Settings → Actions → Runners → New self-hosted runner** → **Windows / x64** 선택.
   화면에 나오는 명령을 PowerShell(관리자)에 차례로 붙여 넣습니다. `config.cmd` 단계에서 묻는 것은:
   - runner group, runner name, work folder: 그냥 Enter
   - **additional labels: `korea`** 입력 (꼭 이 이름. 매일 작업이 이 라벨이 붙은 실행기를 찾습니다)
   - **run as service: `Y`** (PC 를 켜면 실행기가 자동으로 켜짐)
3. **확인**: Settings → Actions → Runners 에 실행기가 **Idle**(초록 점)로 보이면 끝입니다.
   **Actions → 한국 PC 수집 (해외 차단 사이트) → Run workflow** 로 한 번 돌려 보세요.
4. **PC 설정**: 05:47 에 절전·최대 절전 상태면 실행되지 않습니다. 전원 옵션에서 절전 모드를 끄거나,
   BIOS·작업 스케줄러로 05:30 에 깨우도록 설정합니다. PC 가 늦게 켜진 날은 켜지는 대로 수집하고, 그 결과는 다음 날 메일에 들어갑니다.

> **보안**: 공개 저장소에 자체 실행기를 붙이면, 남이 보낸 Pull Request 의 워크플로가 내 PC 에서 돌 수 있습니다.
> **Settings → Actions → General → Fork pull request workflows** 에서 **Require approval for all external contributors** 를 켜 두세요
> (이 저장소의 워크플로는 Pull Request 로 한국 PC 를 쓰지 않습니다). 저장소를 비공개로 바꿔도 됩니다.

## 동작 방식

```
sources.yaml 의 게시판·API ──▶ 수집 ──▶ 강사 공고 판별·분야 분류 ──▶ DB(신규·중복 판정)
                                                                        │
       메일(강사잇다 양식 첨부) ◀── 공고문에서 수업 일정 등 찾기 ◀──────┘
```

- 수집 기록(SQLite)은 저장소의 `state` 브랜치에 저장됩니다. 지우면 다음 실행 때 모든 공고가 다시 신규로 옵니다.
- 한국 PC 가 읽은 결과는 `state-korea` 브랜치(korea.db)에 저장되고, 매일 메일 작업이 가져와 같은 판별·중복 처리를 거쳐 함께 보냅니다.
- 메일 발송에 실패한 날의 공고는 다음 날 다시 신규로 보내집니다.
- 한 사이트가 고장 나도 나머지는 계속 수집하고, 실패한 사이트는 끝에서 한 번 더 시도합니다. 그래도 안 되면 메일 상단에 표시됩니다.
- 수집이 20분을 넘으면 남은 사이트는 건너뛰고 메일부터 보냅니다 (건너뛴 사이트는 보충 수집 대상).

## 규칙 바꾸기

- **강사 공고로 볼 단어·뺄 단어**: `config/keywords.yaml` 의 `include` / `exclude` / `result_notice`
- **포함 단어가 들어 있지만 다른 뜻인 낱말**: `config/keywords.yaml` 의 `include_ignore` (예: '건강사업' 속 '강사')
- **게시판 하나만 포함 단어를 좁히기**: `sources.yaml` 의 그 게시판 `options.include`
- **합격자 발표 같은 결과공고도 받기**: `keep_result_notices: true`
- **분야 분류**: `config/keywords.yaml` 의 `categories` (위에서부터 먼저 맞는 분야, `!단어` 가 있으면 그 분야는 건너뜀)
- **게시판 추가**: `config/sources.yaml` 에 항목 추가. 구조를 모르면 먼저 진단합니다.
  - `scripts/probe_urls.txt` 에 목록 주소를 한 줄에 하나씩 적어 올리면 **사이트 진단 (probe)** 이 자동으로 돌아
    게시판 파서가 읽은 글 몇 건·링크 형태를 로그에 보여 줍니다 (줄 끝에 `legacy_tls`·`short_headers` 를 적으면 그 주소만 연결 옵션을 켬).
  - 또는 **Actions → 사이트 진단 (probe) → Run workflow** 에서 `--no-reach --parse --url <목록 주소>` 로 확인하고,
    넣은 뒤에는 같은 화면의 `check` 칸에 소스 id 를 적어 시험 수집합니다.

## 직접 실행 (개발용)

```bash
pip install -r requirements-dev.txt
python -m pytest                                                     # 테스트
PYTHONPATH=src python -m gyeongbuk_jobs check-source gbe_afterschool  # 게시판 하나 시험 수집
PYTHONPATH=src python -m gyeongbuk_jobs run --no-mail                # 전체 수집, 엑셀만 out/ 에 생성
PYTHONPATH=src python -m gyeongbuk_jobs send-test-mail               # 메일 설정 확인 (SMTP_* 환경변수 필요)
```

`tests/fixtures/busan_*.html` 은 부산판에서 가져온 실제 게시판 화면으로, 경북판도 같은 게시판 파서를 쓰므로
여러 게시판 형태를 그대로 읽는지 확인하는 회귀 시험에 씁니다.
